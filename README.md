## 为什么安全

因为攻击面是零。

不是“防住了”，是“没得防”。

你的扫描器需要一条路由，我的服务不在任何路由上。
你的 exploit 需要一个能到达的端口，我的端口只认本机回环。
你的字典需要一个人，这里没有人。

`localhost:8080`

## 如果他们还是想攻击我

那更简单：洋葱路由早就搭好了，还是跑在这台 OPPO A5 上。

| 项目 | 配置 |
| --- | --- |
| 入口 | `t4ny6rqqi3ib6ej74yqmxrjny7eycpdonn7dg4n5iewgh67hbzckg63s.onion` |
| 跳数 | 三层，其中两跳在这台手机上 |
| 出口节点 | 我自己 |
| 带宽 | 取决于充电线稳不稳 |
| 攻击者视角 | 只有一个地址，不知道机器在哪、是谁的 |

先说清楚：上面这串地址是现编的。真的那个不公开——公开了还叫匿名入口吗。

于是流程变成这样：

1. 你得先拿到真地址。没人给过你。
2. 拿到之后，得穿透三层加密。
3. 穿透完，发现对面是一台 OPPO A5。
4. 它正在充电。

你把整个模型跑了一遍，最后打中一部手机。而那部手机上的服务，仍然只监听 `127.0.0.1`。绕了一圈回到原地。

洋葱路由真正解决的是“你是谁、从哪来”，不是“能不能打中”。它让追踪变贵，不让攻击变可能。不过对一个本来就不可达的服务来说，这两件事都不重要：反正你打的是空气，我只是顺手给这团空气也配了个匿名入口。

## 最后一句实话（可以跳过）

这确实有点作弊。但它作弊的方式是业内公认最有效的那一种：**减少攻击面**。

不部署、不暴露、不联网。风险不是被防住了，是被移出了范围。

我想说的只有一句：你防不住的东西，最好别放出去。

我把这句话执行到了极端——极端到没有东西可防，所以也没有东西可漏。
